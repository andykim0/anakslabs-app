# DEMO-STYLE-LEARNING — 병원 사이트 79곳 디자인 언어 학습

현 데모 템플릿의 시각 수준이 "인라인 스타일 기본기"에 머문다는 판정에 따라, 코퍼스 `corpus-2026-08/sites/`(병원 79곳)에서 디자인 언어를 추출해 템플릿 디자인 시스템의 근거를 만든다. **분석·설계 문서까지이며 구현은 하지 않는다.**

---

## 0. 방법론과 커버리지 — 먼저 한계부터

| 항목 | 값 |
|---|---|
| 코퍼스 | 79곳 (KR 001–055, US 056–079) |
| DOM 문서가 있는 곳 | **47 / 79** |
| 라이브 fetch로 보강 | **14곳** (US 중 DOM 없는 전부, 읽기 전용 GET) |
| 최종 프로파일 | **61곳** — KR 36 / US 25 |
| 미분석 | 18곳 (KR, DOM 없음 + 라이브 미보강) |

**분석 대상은 사이트당 최대 3개 문서**(홈 + 하위 2)의 DOM 전문이다. 인라인 스타일·`<style>` 블록·클래스 서명·Google Fonts 링크에서 신호를 뽑았다.

**정직하게 밝혀둘 한계 세 가지.**
1. **외부 CSS 파일 내부는 읽지 않았다.** 팔레트·타이포는 인라인/임베디드 선언에서만 추출했으므로, 스타일을 전부 외부 파일에 둔 사이트는 액센트가 `None`으로 잡힌다. 아래 'N 미분류' 13곳 중 상당수가 이 경우이며 **디자인이 없는 게 아니라 측정이 닿지 않은 것**이다.
2. **KR 36곳 중 18곳은 DOM이 없어 빠졌다.** KR 표본은 절반 규모로 봐야 한다.
3. 색 계열의 **hue 중앙값은 빨강 계열에서 신뢰할 수 없다**(0°/360° 경계를 넘나들어 산술 중앙값이 무의미). 빨강 계열은 대표 RGB로만 읽어야 한다.

### 시장이 갈리는 지점 — 이미지 밀도

| 시장 | 페이지당 이미지 중앙값 |
|---|---|
| **KR** | **32.0** |
| **US** | **11.7** |

**2.7배 차이다.** KR은 이미지가 곧 콘텐츠인 랜딩 구조(시술 전후·가격표·이벤트 배너를 전부 이미지로 굽는다)이고, US는 텍스트와 컴포넌트로 말한다. 이것이 두 시장의 가장 큰 구조적 차이이며, **우리 제품(사이트를 생성해주는 SaaS)에는 US 방식이 맞다** — 이미지로 구운 콘텐츠는 생성·수정·검색 어느 쪽에도 불리하다.

### 레이아웃

- **컨테이너 최대폭 1200px**이 데스크톱 표준(1024·980이 그다음). 767/768은 브레이크포인트다.
- **타이포 스케일**은 13·14·15·16·18 / 22·24·26·30·32의 두 덩어리로 갈린다. **42px 이상 헤드라인 선언이 인라인에서 거의 안 잡힌다** — 큰 제목은 대부분 이미지이거나 외부 CSS에 있다.

### 히어로 슬라이더를 권하지 않는 이유

69%가 쓰지만, 시각 완성도 상위(7–8점) 사이트들은 슬라이더 대신 **정적 히어로 + 명확한 단일 메시지**를 쓴다. 슬라이더는 만들기 쉬워서 많이 쓰이는 것이지 좋아서 많이 쓰이는 것이 아니다.

- **형태**: 라운드 4px, 그림자 최소, 1200px 컨테이너

## 5. 구현자(app-fixer)에게 넘기는 판단

1. **넘어야 할 하한선은 `#2ea3f2`다.** Divi 기본 블루를 그대로 쓴 사이트가 US 상위 코퍼스에 3곳 있다. 우리 데모가 "테마 기본값 같다"는 인상을 주면 실패다.
2. **H1 44px 이상 구간이 비어 있다.** 코퍼스 대부분이 큰 제목을 이미지로 굽거나 외부 CSS에 숨겼다. 제대로 된 타입 스케일을 텍스트로 구현하는 것만으로 차별화가 된다.
3. **KR 방식(페이지당 32장)을 따라가지 마라.** 생성형 제품에는 구조적으로 불리하다.
4. **히어로 슬라이더는 기본값에서 빼라.** 69%가 쓰지만 잘 만든 사이트는 안 쓴다.
5. 필수 컴포넌트 넷은 **CTA · 시술 목록 · 예약 블록 · 의료진 프로필**(전부 84% 이상). 이 넷이 없으면 병원 사이트로 안 보인다.
