# 국내 병원 웹사이트 실측 — 세그먼트 02 (site-list 15~27번, 13곳)

## 측정 방식 (모든 항목 공통)
- 로컬 Chromium(Playwright)로 **1440×900 데스크톱 · 390×844 모바일** 2회 렌더. 데스크톱은 전체 높이를 650px 단위로 스크롤해 지연 로드/리빌을 발동시킨 뒤 계측.
- **휘도**: DOM computed 값이 아니라 **실제 렌더 스크린샷 픽셀**에서 상대휘도 `L = (0.2126R + 0.7152G + 0.0722B)/255` 를 섹션 밴드별로 평균. 판정 임계값 — **라이트 `L ≥ 0.65` 또는 밝은픽셀(L>0.65) 비율 ≥ 0.60 / 다크 `L ≤ 0.35` 또는 어두운픽셀(L<0.35) 비율 ≥ 0.60 / 그 사이는 `중간`**. 히어로는 뷰포트 0~900px 밴드 기준(내비 가림 보정치도 별도 산출).
- **섹션**: 섹션 컨테이너의 직계 자식 중 높이 180px 이상·가시 요소. `position:fixed/sticky` 오버레이와 화면 밖 드로어는 섹션에서 제외(플로팅 퀵메뉴가 섹션으로 오계수되는 것을 막기 위함).
- **구성 유형 코드**: 각 섹션의 heading + 앞부분 본문을 한국어 어휘 규칙으로 분류. 규칙에 안 걸리면 `other(...)`.
- **리빌**: 스크롤 전 뷰포트 아래에 있으면서 `opacity<0.15` 또는 `transform≠none` 인 요소를 최대 60개 태깅 → 전체 스크롤 후 같은 요소의 opacity/transform 재측정. 이동 px 는 스크롤 전 `matrix()` 의 tx/ty, 지속·이징은 computed `transition-duration/timing-function`·`animation-*`·AOS 속성에서 취득.
- **플로팅/스티키**: 데스크톱 중간 스크롤 지점 + 모바일 중간 스크롤 지점에서 `position:fixed|sticky` 이면서 뷰포트와 겹치는 블록을 열거, 내부 링크의 href/라벨로 채널 종류 분류.
- `없음` 판정은 홈 전체 innerText 전수 정규식 검색과 섹션별 렌더 캡처 판독이 **둘 다** 통과할 때만. 하나라도 어긋나면 `미확인`.
- **분류 2필드(진료 유형·규모)**: 별도 패스로 홈에서 **GNB/헤더 링크 라벨 전량 · 진료과 어휘 출현 수 · 지점명·지점 전화·주소·사업자 정보 · 의료진 링크 라벨**을 추출해 판정했다. GNB 진료 메뉴 구성이 진료 유형의 1차 근거, 지점명과 지역번호가 다른 전화번호의 복수 여부가 규모의 1차 근거다. **하위 페이지는 열지 않았다** — 홈에서 확증되지 않으면 `미확인`.

> ### ⚠ 이 교차표는 현재 상태로 해석에 쓸 수 없다 — 결측이 유형과 상관되어 있다

# ★ 반복 패턴 (하우스 스타일 의심) — 시장 빈도와 분리

이 13곳은 **한 대행사 포트폴리오**이므로, 아래 항목은 "국내 병원 웹 시장의 빈도"가 아니라 **제작사의 반복 습관**일 가능성이 높다. 시장 일반화에 쓰지 말 것.

### 하우스 스타일로 강하게 의심되는 것 (표본 내 편중이 뚜렷)

1. **「우측 세로 아이콘 퀵메뉴 + 상단 고정 가로바」 2단 조합** — 6곳(55%). 아이콘 라벨 구성까지 유사하다: `전화상담 / 비용문의(또는 온라인상담) / 카카오톡 / 오시는길 / TOP`. misoro·limedent·cnuclinic·hooclinic·marbleps·champodonamu 에서 반복.
2. **본문바로가기 스킵 링크가 화면 밖 `fixed` 로 남아 있는 패턴** — faceps · iniqueps · limedent · cnuclinic · misoro 5곳에서 동일하게 `top=-40, 1440×40` 형태로 검출. **동일 템플릿에서 파생됐다는 강한 흔적.**
3. **히어로에 채움 버튼을 두지 않고 CTA 를 플로팅으로 몰아주는 설계** — 11곳 전부(버튼형 자체가 있는 곳도 kseye 1곳뿐). 시장 전체가 그렇다기보다 **제작 규칙**으로 보인다.
4. **폰트 스택 `"Noto Sans KR", 맑은고딕/Nanum Gothic` 이 그대로 반복** — misoro · limedent · iniqueps · kseye · faceps · cnuclinic 6곳에서 거의 동일한 폴백 체인.
5. **히어로 카피를 이미지에 굽는 관행** — 히어로 텍스트 색을 DOM 에서 읽을 수 없는 곳이 7곳(64%). 슬라이드형 히어로에서 특히 일관.
6. **진입 팝업 + 딤 레이어 사용** — 측정한 11곳 중 **5곳에서 진입 팝업 검출**(champodonamu · kseye · marbleps · hooclinic · rebornps). 「오늘 하루 그만 보기」 문구가 동일.

### 하우스 스타일이라 보기 어려운 것 (표본 내 분산이 큼)

- **모션 수준**: GSAP ScrollTrigger 대형 사이트(champodonamu · cnuclinic)부터 **모션 라이브러리 0인 사이트 4곳**까지 스펙트럼이 넓다. 제작 시기·예산 차이로 보인다.
- **밀도**: 1화면 게이트웨이부터 23화면 대형 사이트까지 20배 이상 차이.
- **타이포 개성**: hooclinic 의 MaruBuri 세리프, rebornps 의 캘리그래피 4종, marbleps 의 65px 헤딩 — 서로 공유되지 않는 개별 선택.
- **톤 리듬**: 급전환 3회인 faceps 와 전환 0회인 5곳이 공존.

### 표본 성격상 특히 주의할 점

- **게이트웨이/스플래시 홈이 3곳(27%)** — misoro · kseye · ppeum. 시장 일반 빈도로 보기엔 지나치게 높다. 다지점 네트워크·앱형 클라이언트가 한 대행사에 몰린 결과일 수 있다.
- **13곳 중 2곳(15%)이 접근 불가**(makeps 404 · ysfirst NXDOMAIN). 포트폴리오 목록이 갱신되지 않았다는 뜻이며, **나머지 사이트들도 제작 시점이 오래됐을 가능성**을 시사한다.
- **진료 유형이 심하게 치우쳐 있다** — 성형외과 4곳(36%)에 한의원 2곳, 나머지 5개 유형은 각 1곳뿐. 목록 순서로 분할한 세그먼트라 이 구성은 **우연이며, 유형별 시장 빈도로 읽으면 안 된다.** 유형 교차는 n=4인 성형외과에 대해서만 패턴 서술이 가능하고, 나머지는 개별 사례로만 기록했다.
- **`단일원장` 판정이 0곳**인 것도 시장 사실이 아니라 **홈에서 원장 수를 확증할 수 없었던 결과**다(4곳이 `미확인`). 하위 `의료진소개` 페이지까지 열면 달라질 수 있으나 이번 조사는 홈 기준이라 확장하지 않았다.

1. **진입 팝업과 딤 레이어를 제거하지 않으면 톤 판정이 뒤집힌다.** rebornps 는 딤 제거 전 「전 섹션 다크」, 제거 후 「전 섹션 라이트」였다(히어로 0.184 → 0.903). champodonamu 도 전환 14회 → 1회로 바뀌었다. 이 리포트의 모든 휘도 값은 **팝업·딤 제거 후 값**이다.
2. **리빌 라이브러리는 폴드 아래를 `visibility:hidden` 으로 감춘다.** DOM 계측을 스크롤 전에 하면 섹션 절반이 사라진다(iniqueps: 6개 → 10개). 이 리포트는 **전체 스크롤 후 DOM 계측**한 값이다.
3. **`animation-duration` 은 애니메이션이 끝나면 computed 값이 0s 로 돌아간다.** 지속 ms 는 리빌이 **진행 중일 때 샘플링**해야 얻어진다. 지속값이 `미확인` 인 사이트는 GSAP 처럼 인라인 스타일을 직접 보간하는 방식이라 이 방법으로도 잡히지 않은 경우다.

   - **「구조적 공허」 단독**(자식 미디어 0 && 텍스트 ≤4자)은 콘텐츠 오제거가 0건이지만, `position:absolute` 인 진짜 딤(`main-popup-bg`)을 놓친다.
   - **두 조건을 AND 로 묶으면 30개 전부 정답이다** — 진짜 딤 4개 제거, 콘텐츠 오제거 0건.

   **권장 판정식** (딤은 「크다」가 아니라 「어둡고 불투명하면서 속이 비었다」로 정의한다):
   ```
   isDimBackdrop(el):
     r     = el.getBoundingClientRect()
     cover = (r.width * r.height) / (viewportW * viewportH)
     bg    = parseRGBA(getComputedStyle(el).backgroundColor)
     L     = (0.2126*bg.r + 0.7152*bg.g + 0.0722*bg.b) / 255
     return cover >= 0.55
        AND bg.a  >  0.15                                    // 불투명해야 함
        AND L     <  0.35                                    // 어두워야 함
        AND el.querySelectorAll('a,button,img,video,iframe').length === 0   // 속이 비어야 함
        AND el.innerText.trim().length <= 4
   ```

   **이 세그먼트 하네스의 실제 동작**: 딤 제거(2번 규칙)는 면적이 아니라 **`fixed` + 뷰포트 90%×90% + 텍스트 ≤4자 + 자식 a/button/img/video/iframe 0개**를 요구한다(`.work-seg02/measure_kr.py` `DISMISS_JS` 2번 루프). 즉 **구조적 공허 조건은 있고 alpha·휘도 조건은 없다.**
   측정한 **23곳(세그먼트 02의 11곳 + 대조용 세그먼트 01의 12곳) 전수 감사 결과 히어로가 삭제된 사이트는 0곳**이다. 제거된 레이어는 전부 이름이 `mainPop`·`pop_c`·`LayerPopup`·`popup0/2`·`cross-popup-slider`·`popupWrap`·`new_pop_swiper`·`pop` 인 진입 팝업이거나 딤(`pbg`·`mask2`·`cxdialog`·`modal`·`termBox`)이었고, 23곳 모두 히어로 섹션이 정상 검출됐다.

   **다만 내 1번 규칙에는 남아 있는 위험이 있다**: 이름 정규식에 `overlay`·`dim` 이 포함돼 있어, `hero-overlay` 같은 클래스를 가진 대형 `fixed` 히어로는 **닫기 문구가 없어도 제거된다**(`named && bigLayer` 로 통과). 23곳에서는 발생하지 않았지만 엔진에 그대로 옮기면 안 된다. **이름 매칭만으로 제거하지 말고, 위 `isDimBackdrop` 을 통과하거나 닫기 문구가 실재할 때만 제거해야 한다.**

5. **슬라이드형 히어로는 로드마다 휘도가 달라진다.** iniqueps 는 반복 측정에서 0.548 / 0.681 / 0.825 / 0.864 로 요동했다. 히어로 톤이 `중간`으로 나온 3곳은 대부분 이 변동 때문이다.
