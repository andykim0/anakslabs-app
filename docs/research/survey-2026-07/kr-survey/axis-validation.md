## 2. ★`location` 축 KR 검증

US 결과: **네트워크분원 8/10(80%) > 단일원장 2/6(33%)** — 분원이 많을수록 `location` 을 둔다.

### KR 결과 (seg01 재코딩 포함, 3개 세그먼트 통합 · 원수 병기)

| 규모 | `location` 보유 | 비율 |
|---|---|---|
| **단일원장** | **3 / 3** | **100%** |
| **다원장** | **12 / 15** | **80%** |
| **네트워크분원** | **4 / 14** | **29%** |
| 미확인 | 4 / 7 | 57% |
| 해당없음(비병원) | 0 / 1 | 0% |

seg01 을 빼고 어휘 일치 세그먼트만 보면: 단일원장 2/2 · 다원장 6/9 · **네트워크분원 3/11(27%)** `auto` — 같은 방향이다.

### 판정: **방향이 US와 정반대다 → 축 기각**

US 는 네트워크분원 80% / 단일원장 33% 로 **분원 많음 = location 있음**.
KR 은 네트워크분원 29% / 단일원장 100% 로 **분원 많음 = location 없음**.

세 규모 구간이 **단조 역방향**(100% → 80% → 29%)으로 늘어서 있어 우연으로 보기 어렵다 `judged`.

**메커니즘(관찰된 구조적 이유)** `judged`
KR 네트워크분원은 홈에 단일 `location` 블록을 두는 대신 **지점 선택자·지점 목록**으로 대체한다 — B07 자생(20지점 선택자) · B03 나누리(4지점별 지표) · seg01 10 goruda·12 doctorpetit(지점 게이트 홈) `auto`. 주소가 하나가 아니라서 "오시는 길" 블록이 성립하지 않는다.

**교란 요인 명시** `judged`
- KR 네트워크분원 14곳 중 **대형 종합병원 4곳이 전부 location X**(B36~B39) 라 비율을 끌어내린다. 이 4곳을 빼면 네트워크분원 4/10(40%) 이지만 **여전히 단일원장 100% 보다 낮아 방향은 유지**된다 `auto`
- KR 단일원장 n=3, US 단일원장 n=6 으로 **양쪽 다 n이 작다**. 방향 반전은 명확하나 효과 크기는 이 표본으로 확정할 수 없다 `judged`
- seg01 `velyb` 는 내 매핑에서 `branch-list→location` 으로 O 가 됐다. 이 매핑을 빼면 네트워크분원 3/14(21%) 로 **방향이 더 강해진다** `auto`
