## 측정 방법 (전 항목 공통)
- **엔진**: 로컬 Chromium(Playwright, headless) · 데스크톱 1440×900 / 모바일 390×844 2회 렌더
- **절차**: DOMContentLoaded → networkidle(≤20s) → 대기 3s → **700px 단위로 전체 스크롤(리빌 트리거)** → DOM 계측 + 섹션별 실렌더 픽셀 캡처 휘도 측정
- **휘도**: 상대휘도 L = (0.2126R + 0.7152G + 0.0722B)/255, 렌더된 픽셀 실측 평균
  - **판정 임계값: L < 0.35 = 다크 · 0.35 ≤ L ≤ 0.65 = 중간 · L > 0.65 = 라이트**
  - 히어로는 상단 고정 내비 영향을 제거한 **y=110~900 밴드(`heroLumBelowNav`)** 를 우선 사용
- **표기 규칙**: `auto` = 스크립트 실측값 그대로 · `judged` = 실측 데이터/전체 캡처를 근거로 한 사람 판단 · `unverified` = 확인 실패
- **`없음` 판정**: 홈 전체 innerText 전수 정규식 검색 + 전체 페이지 캡처 육안, **둘 다 통과할 때만**. 하나라도 불확실 → `미확인`
- **준수**: HTML/CSS·사진·카피 문구·색상 hex·아이콘 수집 0. 자산 다운로드 0. 구조/유형/빈도/수치만 기록.

# ★★ 구성 유형 코드 × 진료 유형 교차 (핵심 산출물)

> n이 유형당 1~4곳으로 매우 작다. **"이 유형은 이 구성"이라는 단정은 아직 불가**하며, 아래는 세그먼트 04에서 관찰된 경향과 **교차 확인이 필요한 가설**을 구분해 적었다.

## A. 성형외과 (n=3 — 42 jwbeauty · 44 rubyps · 49 eyejak)
| # | 코드 |
|---|---|
| 42 | `hero→booking→**videos→beforeafter**→gallery→services→about→providers→trust→booking+reviews→location` |
| 44 | `hero→**reviews+trust→reviews→beforeafter**→services→events→trust(논문)→location→other(회원)` |
| 49 | `other(띠배너)→hero→services→services→other(브리지)→other(3열 게시판)→other(정보타일)→booking` |

- **공통(3/3)**: 히어로 직후에 services 를 두지 않거나(42·44) 두더라도 후기·전후가 반드시 상위에 온다. **`beforeafter` 보유 3/3**, 그중 2곳(42·44)이 **수술 전 사진 로그인 게이팅**.
- **공통(3/3)**: 홈에 **FAQ 없음**, **이벤트는 팝업·게시판으로 처리**.
- **분화**: 규모가 클수록(42 다원장·44 네트워크) `providers`·`trust(논문/학술)` 가 들어가고, 단일원장(49)은 **의료진 블록 자체가 없고** 게시판 3열로 홈을 채운다.
- **가설**: 성형외과는 `hero → (증거: reviews/beforeafter) → services` 순으로, **시술 설명보다 결과 증거를 먼저** 내세운다. n=3이라 교차 확인 필요.
