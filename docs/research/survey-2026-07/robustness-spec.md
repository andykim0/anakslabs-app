# 견고성 테스트 명세 — 측정 완료 사이트 기반 장애 프로필

> **목표 전환**: 제품 지표를 "평균 구성을 잘 재현하는가"에서 **"임의의 병원 URL을 넣었을 때 오류 없이 돌아가는가"**로 옮긴다.
> 이 문서는 **새 측정을 하지 않았다.** 아래 모든 장애 특성은 `kr-survey/segment-*.md` 5개 파일과 `us-survey/segment-*.md` 4개 파일에
> **이미 기록된 내용만** 추출·재배열한 것이다. 원 리포트에 기록이 없는 항목은 `미기록`으로 남겼고 추정으로 채우지 않았다.
> **난이도 등급은 전부 추정치다.** 파이프라인을 실제로 돌린 결과가 아니라, 기록된 장애 특성을 아래 규칙에 대입해 산출한 값이다.

## 0. 표본 범위 — 리드가 말한 79곳과의 차이

| 출처 | 사이트 수 |
|---|---:|
| `kr-01` | 14 |
| `kr-02` | 13 |
| `kr-03` | 13 |
| `kr-04` | 14 |
| `kr-target` | 19 |
| `us-dental` | 11 |
| `us-dental(제외)` | 3 |
| `us-aesthetic` | 7 |
| `us-ortho` | 8 |
| **합계** | **102** |

- 리드가 말한 **79곳**은 KR 목록 54곳 + US 25곳으로 보인다. 그런데 지시가 `segment-*.md` **전부**였고, 그 사이 `kr-survey/segment-target.md`(19곳)와
  `us-survey/segment-dental.md`의 11번째 카드·제외 3곳이 추가돼 **실제 기록된 URL은 102건**이다. 79가 아니라 102을 분모로 썼다.
- 이 중 **99건**만 등급을 매겼다. 나머지 3건(`vennskincare.co.kr` 화장품 이커머스 · `mrbigclinic.com` 태국어 물리치료 · `firesidedc.com` B2B 조달)은
  **병원 사이트가 아니어서 대상에서 제외**했다. 다만 "아무 URL이나 들어온다"는 전제에서는 이런 오입력도 실제로 발생하므로 표에는 남겼다.

## 1. 난이도 등급 규칙 (적용한 그대로)

리드가 준 4단계를 그대로 쓰되, 판정이 갈리는 지점은 아래처럼 못박고 기계적으로 적용했다. **한 사이트가 여러 조건에 걸리면 가장 높은 등급을 준다.**

| 등급 | 트리거 (리포트에 기록된 것만) |
|---|---|
| **L4 실패 예상** | 죽은 도메인(DNS NXDOMAIN·연결 실패·404 스텁·파킹·만료) · 403 · 429 · TLS 인증서 오류 · 무한 리다이렉트 / **전체화면 딤·모달이 기록됐거나, 팝업 때문에 측정값이 오염·반전됐거나, 자동 해제에 실패했다고 기록된 곳** / DOM 은닉(표시량↔DOM 총량 괴리) / 스크롤 가로채기 |
| **L3 어려움** | 본문·제목이 이미지화(본문 0자 섹션 다수, "카피 전부 이미지") / 캐러셀 매장(히어로 슬라이드가 최상위 밴드로 잡혀 섹션 분해 실패) / 섹션 자동 분할 실패 / 극단 규모(≥20화면, ≤1.5화면, 캡처 상한 초과) / 지연 로딩·헤드리스 미렌더 |
| **L2 주의** | H1 부재·0px 숨김·텍스트 0자 / 헤딩 위계 역전 / 제목 일부만 이미지 / 진입 팝업이 기록됐으나 오염은 기록되지 않음 / 슬라이드·리빌 유무 미확인 |
| **L1 통과 예상** | 위 어디에도 걸린 기록이 없음 |

**규칙에서 내가 판단한 두 지점**(리드 원문에 없어 임의로 정한 것이므로 이견이 있으면 되돌린다):

1. **무한 리다이렉트를 L4에 넣었다.** `kseye.co.kr`·`medicubesignature.com`은 https로는 정상이지만 **http URL이 그대로 들어오면 루프에 빠진다.** "아무 URL이나 넣는다"가 전제이므로 실패로 잡는 게 맞다고 봤다.
2. **전체화면 딤이 기록된 곳은 자동 해제에 성공했어도 L4다.** `jk-withme.com`은 닫기 클릭으로 해제돼 오염이 0%였지만, 딤 스크림이 존재한다는 사실 자체가 해제 로직이 없는 파이프라인에서는 곧 실패다. 반대로 소형 레이어 팝업만 기록된 곳은 L2에 뒀다.

## 3. ★ 난이도 등급별 집계 — `ENGINE-ROBUST` 출발 지표

등급 대상 **99곳**(비병원 3곳 제외) 기준.

| 등급 | 곳 | 비율 | 의미 |
|---|---:|---:|---|
| **L1 통과 예상** | 12 | 12% | 접근 정상 · 텍스트 기반 · 표준 규모. 기록된 장애 없음 |
| **L2 주의** | 34 | 34% | 결과는 나오되 제목·위계가 비거나 팝업이 끼어 **일부 필드가 빈다** |
| **L3 어려움** | 25 | 25% | 결과가 나와도 **조용히 틀린다** — 본문이 이미지라 추출량이 실제와 다르고, 섹션 분해가 어긋난다 |
| **L4 실패 예상** | 28 | 28% | **결과가 아예 안 나오거나 정반대로 나온다** — 페치 실패 또는 렌더 오염 |
| 합계 | 99 | 100% | |

**출발선: L1 12% · L4 28%.** 현재 상태를 그대로 두면 임의 병원 URL 99건 중 **28건(28%)이 실패**하고, **53건(54%)은 결과를 신뢰할 수 없다**는 추정이다.

**KR이 US보다 확연히 어렵다.** L4가 KR 34% vs US 14%, L1이 KR 4% vs US 32%다. US 28곳에서 페치 단계 실패는 **2건**(도메인 파킹 1 · HTTP 429 1)뿐이고, **인증서 오류 0건 · 스크롤 가로채기 0건 · 본문 이미지화 0건**이다. KR에서 가장 비싼 세 가지 장애가 US 표본에는 아예 없다.

## 6. ★ 예상 실패 지점 — 이담 전용 가정의 실제 적용 범위

파이프라인에 박혀 있는 이담(`edomclinic.com`) 전용 가정 3종을 전 리포트와 대조했다.

| 엔진 가정 | 전 리포트 출현 | 성립 확인 | 성립 부정 |
|---|---:|---:|---:|
| `.main_tit` / `.content_wrap` (클래스명) | **0회** | **0곳** | **0곳** |
| `sub{c}_{s}[_{d}].php` (URL 패턴) | **0회** | **0곳** | **0곳** |
| `bo_table=tv/edu/story` (그누보드) | **0회** | **0곳** | **0곳** |

세 토큰 모두 9개 리포트 전문에서 **출현 횟수 0**이다(Python `re.findall` 전수 확인). 여기서 결론은 두 갈래인데, 섞으면 안 된다.

**확실한 것** — 이 코퍼스로는 **엔진 가정의 적용 범위를 단 한 곳도 확인할 수 없다.** 즉 현재 근거로 말할 수 있는 성립 곳 수는 **0곳**이다.

**단정하면 안 되는 것** — 이 0은 "99곳 중 0곳이 이담 구조다"라는 **부정의 증거가 아니다.** 원 조사의 준수선이
`HTML/CSS 코드·클래스명 수집 0`을 명시적으로 금지했기 때문에, **애초에 기록될 수 없는 항목**이었다. 코퍼스는 부정이 아니라 **침묵**한다.

### 그래서 실제로 말할 수 있는 것

- **`.php` 경로가 실제로 인용된 곳: 8곳** — `goruda.co.kr`, `iddc.co.kr`, `rubyps.co.kr`, `eyejak.co.kr`, `withme-medi.com`, `resexy.co.kr`, `glowell.co.kr`, `edomclinic.com`
  이것이 `sub{c}_{s}.php` 류 패턴이 **성립할 수도 있는 상한**이다. 성립 여부 자체는 미확인이다.
- 나머지 사이트는 WordPress 2곳 · Shopify 1곳 · imweb 1곳만 확인됐고, **PHP인지 아닌지조차 기록이 없다.**

### 즉시 해야 할 일

1. **이 명세만으로 적용 범위를 결론내지 마라.** 클래스명·URL 템플릿·게시판 파라미터를 수집하는 **별도 1회 스캔**이 필요하다.
   기존 조사와 목적이 달라(디자인 조사 → 파서 호환성 조사) 준수선도 다르게 잡아야 한다.
2. 그 스캔 전까지 엔진의 이담 전용 셀렉터는 **하드코딩된 실패 지점**으로 간주하는 게 안전하다. 아래 3개 가정 모두 **fallback 경로가 없으면
   이담 이외의 사이트에서 조용히 빈 결과를 낸다** — 예외를 던지지 않기 때문에 더 위험하다.

## 7. 엔진이 깨질 지점 — 코퍼스가 직접 보여준 것

클래스명 대조와 별개로, 기록된 장애만으로도 **파이프라인의 어느 단계가 무너지는지**는 특정된다.

| 파이프라인 단계 | 무너뜨리는 입력 | 코퍼스 근거 |
|---|---|---|
| **페치** | DNS NXDOMAIN · 연결 실패 · 파킹 · 404 스텁 · 429 · 인증서 CN 불일치 · http 무한 리다이렉트 | KR 목록의 낡음이 결정적 — `kr-03`은 13곳 중 5곳(38%)이 죽은 도메인이다 |
| **렌더** | 전체화면 딤·모달 · 자동 해제 실패 · 쿠키 배너 | 딤 레이어 하나가 히어로 판정을 `0.184 다크` ↔ `0.903 라이트`로 **완전히 뒤집은** 사례(`rebornps.com`)가 있다 |
| **스크롤/수집** | fullPage.js 스크롤 가로채기 · GSAP 핀 드라이버 · 지연 로딩 실패 | `sooamc.com`은 `window.scrollTo`·마우스 휠 **둘 다 무효**여서 표준 하네스가 히어로만 12회 반복 렌더했다 |
| **섹션 분해** | 히어로 슬라이드가 최상위 밴드로 잡힘 · 복제 슬라이드 · 마퀴 | US 치과 11곳 중 **4곳이 1차 섹션 분할 실패**로 2차 프로브가 필요했다 |
| **텍스트 추출** | 본문·제목이 전부 이미지 · 본문 0자 섹션 | 이 상태에서는 "블록 없음"을 **부정할 수단이 사라진다**(`ilovegangnam.com`은 그래서 블록 5종을 미확인 처리) |
| **제목/위계 추출** | H1 부재 · H1 computed 0px · H1 텍스트 0자 · H1<본문 역전 | 대형 종합병원 4곳(`snubh`·`samsunghospital`·`amc`·`severance`)이 **전부** H1·H2 unverified다 |
| **밀도/분량 산출** | DOM 총량 ↔ 표시량 괴리 | `benjamineye.com` DOM 133,000자 vs 표시 8.2화면 · `velyb.kr` 본문 97,433자 vs 8.2화면 |
| **하위 페이지(의료진)** | 텍스트 0자 · 이름 토큰 0개 · 검색 인터페이스 | 의료진 페이지에서 **이름을 텍스트로 못 얻는 사례가 반복**된다. 대형 병원은 명단이 조회 후 로드된다 |

### 우선순위 제안 (L4 → L1 전환 효율 순)

| 순위 | 조치 | 회수 가능한 곳(추정) |
|---|---|---:|
| 1 | **팝업·딤 자동 해제**(닫기 문구 사전 + 전체화면 fixed 레이어 마스킹) | 10곳 |
| 2 | **URL 정규화**(https 우선 · 리다이렉트 상한 · 인증서 실패 시 http 폴백) | 3곳 |
| 3 | **스크롤 드라이버 대체**(fullPage/GSAP 감지 후 API·섹션 단위 구동) | 4곳 |
| 4 | 죽은 도메인 — 조치 불가, **입력 검증에서 조기 실패 처리** | 13곳 |


1~3번은 서로 겹치는 사이트가 있어(예: `kseye.co.kr`는 무한 리다이렉트와 모달 오염을 둘 다 가짐) 단순 합산하면 안 된다. 중복을 제거하고 **도메인이 죽은 곳을 뺀 실제 회수 가능 대상은 15곳**이다 — L4 28곳의 54%.

남는 **13곳은 도메인이 실제로 죽었거나 차단된 것이라 엔진이 고칠 수 있는 대상이 아니다.** 지표를 발표할 때 이 그룹을 분리하지 않으면, 엔진을 아무리 고쳐도 L4 비율이 내려가지 않아 개선이 보이지 않는다. **엔진 책임 분모는 99곳이 아니라 86곳으로 잡는 것을 권한다.**

## 8. 이 문서의 한계

- **등급은 실행 결과가 아니라 추정이다.** 파이프라인을 이 URL들에 돌려본 적이 없다. 실행 결과와 다를 수 있고, 다르면 실행 결과가 맞다.
- 원 리포트가 다루지 않은 장애는 여기에도 없다. `미기록`이 많다는 것은 **장애가 없다는 뜻이 아니라 그 항목을 아무도 보지 않았다는 뜻**이다.
- 원 조사는 **홈 1페이지 기준**이다. 하위 페이지에서만 나타나는 장애(게시판 페이지네이션, 상세 페이지 템플릿 편차)는 이 표에 잡히지 않는다.
  엔진 가정 3종 중 2종(`sub{c}_{s}.php`, `bo_table=`)은 **하위 페이지 패턴**이라, 홈 기준 조사로는 원리적으로 검증할 수 없었다.
- KR 표본 54곳은 **한 대행사 포트폴리오**이고 19곳은 별도 선정이다. 장애 분포가 한국 병원 사이트 전체를 대표하지 않는다.
- 측정 시점은 2026-07-31 1회다. 도메인 생사·팝업 유무는 시간이 지나면 달라진다.
