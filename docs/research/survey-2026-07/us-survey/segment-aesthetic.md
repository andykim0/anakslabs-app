# US 에스테틱 세그먼트 실측 — 성형외과 · 피부과 · 안과 7곳

측정일 2026-07-31 · 측정자 us-survey-aesthetic

## 측정 방법 (재현 경로)

- Chrome 확장(claude-in-chrome)이 세션 내내 미연결 상태였다. 대신 **Playwright + 헤드리스 Chromium**으로 실제 홈 URL을 직접 로드해 측정했다. 하네스·목업·투영 없음, 전부 실 페이지 렌더 결과다.
- 데스크톱 1440×900, 모바일 390×844 두 뷰포트로 각각 로드 → 지연 로딩·스크롤 리빌 유발을 위해 페이지 끝까지 단계 스크롤 → 히어로/중간/풀페이지 스크린샷 + DOM 계측.
- **톤(6번)은 DOM이 아니라 렌더된 픽셀에서 측정했다.** 풀페이지 스크린샷을 30px 가로 밴드로 잘라 밴드별 평균 휘도를 구하고, 어두움(<100)/중간/밝음(>190)으로 분류해 구간 전환을 셌다. DOM 배경색만 보면 풀블리드 사진 위 텍스트 섹션을 놓치기 때문이다.
- 섹션 구분(2번)은 DOM 자동 분할이 3개 사이트에서 단일 래퍼로 붕괴해 신뢰할 수 없었다. **풀페이지 스크린샷 육안 판독을 최종 근거로 삼았고**, DOM 수치는 보조로만 썼다.
- 오버레이(프로모 모달·구독 모달)는 닫기 컨트롤로만 해제했다. **쿠키 동의 배너는 수락하지 않았다** — 그래서 일부 캡처 하단에 배너가 남아 있으나 측정 항목에는 영향 없다.
- 자산 다운로드 0. HTML/CSS 코드·색상 값·카피 문구·아이콘·사진 미수집. 아래는 구조·유형·빈도만 기록한다.

### 선정 기준과 선정 과정

검색 순위·광고 노출은 선정 기준에서 배제했다. 대신 **디자인 에이전시 포트폴리오와 디자인 라운드업 게재 여부**를 1차 풀로 삼고, 실제 로드해 본 뒤 디자인 수준으로 걸렀다.

측정했다가 최종 7곳에서 뺀 3곳 (투명성 차원에서 기록):

| 제외 | 사유 |
|---|---|
| drneilzemmel.com, jpfarkasmd.com | millercosmeticsurgery.com과 **동일 에이전시 템플릿**. 하단 고정 가로바·우측 슬라이드인 프로모 패널·접근성 위젯 배치가 3곳 모두 픽셀 단위로 동일했다. 3개를 독립 표본으로 세면 빈도가 부풀려지므로 대표 1곳(miller)만 남겼다 |
| mkdermatology.com | 디자인 라운드업에 있었으나 실제로는 구형 템플릿 사이트(모션 0, 섹션 2개, 하단 저작권 표기 2017). "디자인 수준이 높은 곳 위주" 기준에 미달 |

최종 구성은 성형외과 2 · 피부과 3 · 안과 2다.

## 추가 측정 A — 타입 스케일 비율 (H1 : H2 : 본문, px)

computed font-size 기준. 시맨틱 태그가 시각 위계와 어긋나는 사이트가 많아(H1 부재, H2가 H1보다 큼) **시각적 기준**으로 잡았다: H1 = 히어로 영역 내 최대 표시 텍스트, H2 = 히어로 아래 섹션 헤딩의 최빈값, 본문 = 80자 이상 문단의 최빈값. 고정 헤더·내비는 제외.

| 사이트 | H1 : H2 : 본문 | H1/본문 | H2/본문 | 비고 |
|---|---|---|---|---|
| miller | **미확인 : 34 : 16** | 미확인 | 2.1 | **히어로 헤드라인이 텍스트가 아니라 이미지**다. 히어로 내 최대 실텍스트가 18px뿐이라 H1 픽셀 측정 불가 → 미확인. 섹션 헤딩은 34px 최빈, 상단값 58px |
| madnani | **40 : 32 : 18** | 2.2 | 1.8 | 7곳 중 가장 평평한 스케일 |
| parkcity | **84 : 39 : 17** | **4.9** | 2.3 | 7곳 중 대비 최대 |
| moderndermct | **111 : 32 : 23** | 4.8 | 1.4 | H1 절대값 최대(111px). 본문도 23px로 최대라 H2/본문 대비는 오히려 최소 |
| campbell | **64 : 31 : 16** | 4.0 | 1.9 | |
| benjamin | **64 : 48 : 20** | 3.2 | 2.4 | 카드 단위 헤딩은 24px로 따로 존재(3단 위계) |
| maloney | **43 : 29 : 16** | 2.7 | 1.8 | 히어로 텍스트가 후기 인용문 로테이션이라 H1이 상대적으로 작다 |

## 추가 측정 B — 스크롤 리빌 파라미터

측정 방식: 페이지 로드 후 **스크롤 전 상태**에서 뷰포트 아래 요소들의 pre-reveal 상태(투명도·transform 오프셋·transition duration·timing function)를 읽었다. 캐러셀 트랙·패럴랙스·sticky로 인한 대형 오프셋(|이동| 150px 초과)은 리빌이 아니므로 제외했다.

| 사이트 | 이동 거리 | 지속시간 | 이징 계열 | 판정 |
|---|---|---|---|---|
| miller | **50px** (상방 50 / 좌우 ±50, 방향 혼용) | **500ms** | ease · ease-in-out | 이동 동반 리빌 확인 (7곳 중 유일) |
| parkcity | **0px** (페이드만) | **900ms** | ease | 페이드 전용 |
| moderndermct | **0px** (페이드만) | **1000ms** | ease | 페이드 전용 |
| campbell | **0px** (페이드만) | 250 / 500 / 800ms 혼재 | ease · ease-in | 페이드 전용, 구간별 속도 상이 |
| maloney | **0px** (페이드만) | **600ms · 1000ms** 2종 | ease | 페이드 전용 |
| madnani | — | — | — | **미확인** (pre-reveal 후보 0건, 리빌 미검출) |
| benjamin | — | — | — | **미확인** (후보 3건뿐, transition duration 0 — 리빌이라 보기 어려움) |

- **이동 거리를 쓰는 곳은 1/7(14%)뿐이고, 그마저 50px로 짧다.** 나머지 4곳은 전부 이동 0의 순수 페이드다.
- 지속시간 범위 **250~1000ms**, 중앙값 **900ms** — 한국 사이트에서 흔한 300~400ms대보다 확연히 느리다.
- 이징은 **7곳 중 5곳 전부 `ease` 계열 기본값**. 커스텀 베지어를 쓰는 곳은 campbell 일부 구간뿐이다.
- 이 측정은 정밀도가 앞선 diff 방식보다 높아, **maloney(이동 동반→페이드만)와 moderndermct(미검출→페이드 확인) 2건을 정정했다.** 본문 카드·집계표에 반영 완료.

## 추가 측정 C — ★홈 구성 유형 코드

통일 어휘만 사용. 해당 없으면 `other(설명)`. 섹션 순서는 풀페이지 스크린샷 판독 기준이며, 위 "섹션 순서" 항목과 1:1 대응한다.

| 사이트 | 구성 코드 |
|---|---|
| **miller** | `hero→about→services→videos→about→providers→trust→reviews→trust→trust→other(social feed)→other(blog)→booking` |
| **madnani** | `hero→providers→videos→about→trust→providers→gallery→about→booking` |
| **parkcity** | `hero→providers→about→services→events→insurance→about` |
| **moderndermct** | `hero→about→services→providers→reviews→booking` |
| **campbell** | `hero→about→trust→services→providers→reviews→other(secondary hero)→events→events→other(blog)→videos` |
| **benjamin** | `other(news ticker)→hero→other(blog)→about→reviews→videos→other(optical retail)→booking` |
| **maloney** | `hero→trust→about→trust→services→providers→videos→reviews→about→faq→reviews→services→trust→about→services→other(cost calculator)→insurance→booking` |

### 구성 유형 요약

**공통 골격.** 7곳 전부 `hero`로 연다(7/7). 히어로 **바로 다음이 `about` 또는 `providers`인 곳이 5/7(71%)** — 예외는 benjamin(블로그 카드가 먼저)과 maloney(스탯 `trust`가 먼저) 2곳이다. 즉 미국 세그먼트는 대체로 **시술 나열보다 "누가 하는가·어떤 곳인가"를 먼저 세운다.**

`services`가 히어로 바로 다음에 오는 곳은 **0곳**이다. 등장하는 5곳에서 첫 `services`는 히어로 기준 +2~+4번째(평균 +2.8), 즉 **전체 3~4번째 블록**이다. 나머지 **2곳(madnani·benjamin)은 홈에 `services` 블록이 아예 없다** — 시술 목록을 홈에서 빼고 하위 페이지로 넘긴 구성이다.

**닫는 방식.** `booking`으로 끝나는 곳 **5곳(71%)** — miller·madnani·moderndermct·benjamin·maloney. 예외는 parkcity(`about` 서술로 마무리)와 campbell(소셜 영상으로 마무리) 2곳. **예약/상담을 마지막 블록에 두는 것이 최빈형**이다.

반복 패턴으로 3개 군이 나온다.

| 유형 | 해당 | 축약 골격 | 특징 |
|---|---|---|---|
| **A. 표준 단문형** (2곳) | moderndermct, parkcity | `hero→about/providers→services→(providers/reviews)→닫기` | 6~7블록, 4.8~5.5화면. 블록당 1역할, 중복 없음. 가장 모사하기 쉬운 골격 |
| **B. 신뢰 반복형** (3곳) | miller, campbell, maloney | `hero→about→…→trust/reviews가 3~4회 분산 반복→booking` | 11~18블록, 10~16화면. **`trust`/`reviews`를 한 곳에 몰지 않고 페이지 전체에 흩뿌린다**(miller 4회, maloney 5회, campbell 2회). 길이가 길수록 반복 횟수가 는다 |
| **C. 콘텐츠 허브형** (2곳) | madnani, benjamin | `hero→(providers\|blog)→videos→…→booking`, 갤러리·블로그·리테일 등 별도 자산 블록 보유 | 8~9블록. 홈이 하위 콘텐츠(갤러리·블로그·편집숍)로 보내는 관문 역할. `other()` 비중이 가장 높다 |

**어휘 사용 빈도** (7곳 합산, 중복 포함): `about` **12회** · `trust`+`reviews` **14회**(trust 8 + reviews 6) · `other` 8회 · `services` 7회 · `providers` 7회 · `reviews` 6회 · `videos` 5회 · `booking` 5회 · `events` 3회 · `insurance` 2회 · `faq` 1회 · `gallery` 1회 · `beforeafter` **0회** · `location` **0회**.

단일 최다는 신뢰 레이어(`trust`+`reviews` 14회)이고, 그다음이 `about` 12회다. **`services`(7회)보다 신뢰·소개 블록이 두 배 많다** — 이 세그먼트의 홈은 카탈로그가 아니라 설득 문서에 가깝다.

**유형 분류에 쓸 때 유의점 2가지**
1. `beforeafter`와 `location`은 **이 세그먼트 7곳에서는** 홈 구성 요소로 한 번도 나오지 않았다. 다만 이는 **에스테틱 세그먼트 로컬 관측이지 전역 어휘 판정이 아니다** — US 치과 세그먼트에서는 `beforeafter`·`gallery`가 실제로 출현한다(타 에이전트 측정). 어휘는 그대로 유지하고, **진료과별 출현 여부**로 읽어야 한다. (초판에서 "사어 취급 권장"이라 쓴 것은 로컬 관측을 전역 결정으로 올린 과잉이라 철회한다.)
2. `trust`와 `reviews`는 코드상 분리했지만 실제로는 거의 항상 인접·중첩된다(후기 + 인증로고 + 언론로고). 유형 분류 시 두 토큰을 하나의 "신뢰 레이어"로 묶어 세는 편이 패턴이 선명하다.

## 세그먼트 요약 소견

1. **히어로는 "어두운 풀블리드 사진 + 흰 텍스트"가 사실상 기본형**(6/7). 밝은 히어로는 1곳뿐이고 그곳은 사진 대신 일러스트를 썼다.
2. **스탯 배지와 히어로 슬라이드는 미국 세그먼트에서 소수파다.** 히어로 내 스탯 배지 **0/7**, 히어로 슬라이더 **2/7**. 게다가 슬라이드 2곳 모두 "시술 종류를 넘기는 캐러셀"이 아니라 공지·후기 성격의 순환이다. 한국 병원 사이트 관행과 가장 크게 갈리는 지점이다.
3. **전후사진을 홈에 노출하는 곳은 0/7.** 갤러리는 별도 페이지로 밀고 홈에는 진입 CTA만 두거나(2곳) 아예 없다.
4. **필수 3종은 의료진 프로필·후기/신뢰신호·예약 CTA(각 100%)**. 반대로 FAQ·보험은 각 14%로 홈 구성 요소가 아니다.
5. **신뢰신호는 거의 항상 중첩된다** — 후기 + 학회/인증 로고 + 언론 로고를 2~4중으로 쌓는다(7곳 전부).
6. **톤은 "밝은 바탕 + 어두운 밴드 2개(히어로·푸터)" 샌드위치가 최빈형**(3/7). 본문 전반을 교차시키는 곳은 페이지가 길어질 때(11.7·16.3화면) 나타난다.
7. **모션 0인 사이트는 없다.** 다만 대부분 캐러셀(86%)이고, 스크롤 리빌은 71%가 쓰되 **거의 전부 이동 없는 페이드**다. 이동을 동반한 리빌은 **14%(1곳)**뿐이다.
8. **플로팅 CTA는 71%지만 형태는 가벼운 쪽으로 수렴한다** — 세로 스택형 0%, 채팅 버튼 1개형이 43%. 무거운 하단 가로바는 에이전시 템플릿 계열에서만 나왔다.
